## 1. 模块概述

赛训报告是 UR-ESPORTS CS2 赛训数据中心的核心前端页面，位于 `https://ur-esports.cn`（路由 `/training-report`）。

**核心能力**：在选定日期范围内，将「训练日志」「比赛数据」「简报条目」三个维度的数据联动聚合，展示训练赛全景。

**设计原则**：
- **三表联动校验** — 只有当某个日期 + 对手在 `training_sessions`（有回合）、`training_rounds`（有数据）、`matches`（有比赛记录）三者同时存在时，才计入统计
- **轻量统计 + 明细可下钻** — 概览卡片展示关键指标，鼠标点击即可钻取到回合级细节

## 2. 数据架构

### 2.1 核心数据表

| 表名 | 用途 | 关键字段 |
|---|---|---|
| `training_sessions` | 训练赛次 | `id`, `match_date`, `opponent` |
| `training_rounds` | 训练回合明细 | `id`, `session_id`, `round_number`, `map_name`, `issue_*`, `players_involved`, `round_result` |
| `matches` | 比赛记录 | `id`, `match_date`, `opponent`, `map_name`, `result`, `our_score`, `their_score`, `match_type` |
| `briefing_items` | 简报指令 | `id`, `session_id`, `tactic_id`, `sort_order` |
| `tactics` | 战术总表 | `tactic_id`, `name`, `map_name`, `team_side` |
| `players` | 选手名单 | `id`, `nickname` |
| `player_stats` | 选手战绩 | `match_id`, `player_id`, `kills`, `deaths`, `adr`, `rating` |
| `special_events` | 特殊事件 | `date`, `note`（如放假、被放鸽子） |

### 2.2 三表关联关系

```
training_sessions ──1:N──> training_rounds (session_id)
training_sessions ──1:N──> briefing_items (session_id)

matches ──(日期+对手)──> training_sessions
  匹配逻辑：match_date (date only) + opponent (case-insensitive)
```

### 2.3 数据完整性过滤

所有从 `matches` 表查询的 SQL 必须附加以下过滤条件：

```sql
AND opponent NOT IN ('match_data', 'OPPONENT', '___')
AND match_date IS NOT NULL AND match_date != '' AND length(match_date) >= 8
AND map_name IS NOT NULL AND map_name != ''
```

`training_sessions` 表同理：

```sql
AND opponent NOT IN ('OPPONENT', '未知', '___')
```

## 4. 三表联动校验逻辑（核心机制）

### 4.1 背景

早期版本中 `total_matches`（来自 training_sessions + training_rounds）和 `total_wins/total_losses`（来自 matches 表）分别独立查询，互不校验。当某个日期只有 match 数据没有训练日志时，会出现「0 场训练赛却有 2 胜」的矛盾显示。

### 4.2 校验流程

```
1. 查询 matchSummary（training_sessions INNER JOIN training_rounds）
   → 提取 validSessionKeys = Set of "date|opponent" (lowercase)

2. 查询 allMatches（matches 表，带完整性过滤）
   → 遍历每条 match，其 key = "date|opponent(lowercase)"
   → 若 key ∉ validSessionKeys → 跳过
   → 否则计入 filteredMatches

3. 用 filteredMatches 重新计算 validatedWins / validatedLosses / validatedDraws

4. response.overview.total_wins = validatedWins
   response.overview.total_losses = validatedLosses
```

### 4.3 关键代码位置

`backend/routes/training.js` 第 1113-1148 行（`validSessionKeys` 构建 + `filteredMatches` 过滤 + `validatedMap*` 计算）和第 1296-1299 行（response 赋值）。

1. **数据库修改前必须备份**：`cp ur_esports.db ur_esports.db.bak.YYYYMMDD`
2. **代码修改后必须重启 PM2**：`pm2 restart ur-esports`
