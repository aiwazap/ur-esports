# UR Esports 首页 Hero 5 秒循环视频需求说明

- 文档版本：v1.0
- 日期：2026-07-13
- 目标页面：`http://127.0.0.1:5174/overview`
- 实施目录：`D:\Agent files\codex\projects\worktrees\ur-esports\faceit-sea-task-board`

## 1. 需求目标

将首页 Hero 当前静态底图升级为 **5 秒无缝循环视频底图**，增强电竞氛围和视觉流畅度，同时保持页面文字、按钮、标签、数据和展开/收起交互均为真实 HTML，不把 UI 烘焙进视频。

最终效果必须满足：

1. 首次进入首页时，Hero 展开并从视频第 0 秒开始播放。
2. 视频播放满 5 秒后，Hero 按现有规则自动收起一次。
3. 用户手动展开 Hero 后，视频从第 0 秒重新播放并持续循环。
4. 用户手动展开后不再自动收起，只能由用户主动收起。
5. 视频加载失败、网络慢或用户启用“减少动态效果”时，自动显示静态底图。

## 2. 视觉基准

1. 参考底图：`frontend/public/reshape/home/hero-wide.png`。
2. 最终画面比例：**10:3**。
3. 主色固定为深海军蓝、电竞蓝、青色霓虹和紫色能量光。
4. 固定当前构图：左侧留给标题、说明、按钮和三个功能标签；右侧保留机甲龙、UR 主视觉和霓虹地台。
5. 绿色框区域的三个功能标签继续由 HTML 渲染：
   - 准星图标：`CS2 DIVISION`
   - 锁图标：`Internal Platform`
   - 地球图标：`Multi-language`

## 3. 视频内容要求

### 允许的动态

1. 机甲龙轻微呼吸、重心起伏或极小幅度悬浮。
2. 耳侧能量环、地面圆环和霓虹边缘进行周期性呼吸发光。
3. 背景加入缓慢移动的数据网格、扫描光、微粒和能量光带。
4. 地面倒影与环境光进行轻微明暗变化。
5. 镜头只允许极轻微的景深或不超过约 1.5% 的推拉，不改变主体位置。

### 禁止出现

1. 禁止镜头切换、摇镜、明显缩放或构图漂移。
2. 禁止新增角色、文字、按钮、图标、数据卡或其他 UI。
3. 禁止机甲龙、UR 标识、眼镜、能量环发生变形、融化或闪烁。
4. 禁止背景突然换色、亮度跳变、首尾画面跳帧。
5. 禁止在视频中烘焙“UR Esports 赛训数据中心”、按钮、三个功能标签和实时 KPI。

## 4. Seedance 2.0 生成要求

Seedance 2.0 可以用于本需求。官方支持图像参考生成视频、4～15 秒时长及最高 1080p 输出，因此 5 秒视频满足模型规格。

推荐调用模型：`doubao-seedance-2-0-260128`。

调用方式优先使用火山方舟官方 API：

- 创建任务：`POST https://ark.cn-beijing.volces.com/api/v3/contents/generations/tasks`
- 鉴权：本机环境变量 `ARK_API_KEY`
- 安全要求：API Key 只保存在本机环境变量或本地 `.env`，不得写入 Git、需求文档或聊天内容。

### 可直接使用的生成提示词

```text
使用提供的 UR Esports 电竞头图作为唯一构图参考，固定镜头，严格保持机甲龙、UR 主视觉、地面平台和背景布局不变。制作 5 秒循环动画：机甲龙只有非常轻微的呼吸和悬浮，耳侧蓝紫能量环缓慢脉冲，地面同心圆霓虹光环平稳旋转并呼吸发光，背景数据网格、微粒和扫描光缓慢移动，地面倒影随光线轻微变化。整体为深海军蓝、电竞蓝、青色霓虹和紫色能量光，运动克制、稳定、连续、无抖动。首帧和末帧的构图、主体位置、亮度和能量环状态必须一致，便于无缝循环。画面中不要新增文字、按钮、图标、数据面板或角色，不要改变机甲龙与 UR 标识结构，不要镜头切换，不要大幅推拉，不要闪烁，不要形变。
```

生成时至少保留 3 个候选结果，优先选择主体最稳定、首尾差异最小、Logo 形态最完整的一条进入后处理。

## 5. 最终视频技术规格

1. 时长：**精确 5.000 秒**。
2. 最终尺寸：**1920 × 576**。
3. 最终帧率：优先保留 Seedance 原生 **24fps**，不强制插帧，避免产生伪影。
4. 主格式：H.264 MP4，`yuv420p`，无音轨，启用 Web Fast Start。
5. 兼容格式：WebM，作为支持浏览器的备用源。
6. 单文件目标体积：MP4 不超过约 **6MB**。
7. Poster：继续使用 `hero-wide.png`。
8. 文件命名：
   - `frontend/public/reshape/home/hero-loop.mp4`
   - `frontend/public/reshape/home/hero-loop.webm`
   - `frontend/public/reshape/home/hero-wide.png`

## 6. 无缝循环后处理

Seedance 生成结果不能直接视为绝对无缝，必须进行本地后处理：

1. 核对首帧和末帧的构图、亮度、主体位置及能量环状态。
2. 对首尾约 0.3～0.5 秒执行环形交叉融合，消除跳变。
3. 裁切并缩放到 1920 × 576，保持主体不变形。
4. 删除音轨，压缩为网页适用码率并启用 Fast Start。
5. 最终再次核对时长必须为 5.000 秒，连续播放 10 次不得出现明显顿挫或闪白。

## 7. 前端嵌入要求

1. 视频位于 Hero 最底层，现有 `.ov8-hero-motion`、标题、按钮、标签和 KPI 继续位于视频上层。
2. 视频元素使用：`autoPlay`、`muted`、`loop`、`playsInline`、`preload="auto"`。
3. 使用 `poster="/reshape/home/hero-wide.png"` 作为首屏和失败兜底。
4. 使用 `object-fit: cover` 和居中定位，不拉伸画面。
5. Hero 收起时暂停视频并重置到第 0 秒，减少后台资源占用。
6. Hero 展开时从第 0 秒播放；手动展开后持续循环。
7. 浏览器拒绝自动播放或视频加载失败时，不影响 Hero 展开、收起、按钮点击和数据展示。
8. `prefers-reduced-motion: reduce` 命中时不自动播放视频，仅显示静态 Poster。

## 8. 验收标准

1. 首次进入首页，Hero 展开并播放一轮视频，5 秒后自动收起。
2. 手动展开后等待超过 5 秒，Hero 仍保持展开，视频继续循环。
3. 连续循环 10 次无明显跳帧、闪白、亮度突变或构图位移。
4. 机甲龙、UR 标识和能量环无 AI 形变。
5. 三个功能标签图标、标题、按钮和 KPI 清晰可读，不属于视频画面。
6. 1920 × 1030、1366 × 768 和 430 × 932 三档视口无横向溢出。
7. 浏览器控制台错误为 0，视频加载失败时静态图兜底生效。
8. `npm run build` 通过；只允许既有 chunk 体积警告。

## 9. 交付物

# v1.1 修订（2026-07-13，华哥新需求，Claude 侧记录）

## 修订原因

华哥明确新的创意方向：**机甲龙要"活"——完成一次转身并摆定 pose；UR Logo 旁的火焰持续燃烧**。
这与 v1.0 的约束冲突（v1.0 只允许轻微呼吸、禁止主体大动作），且"转身+定格"与"无缝循环"天然矛盾，故做如下修订。

## 播放策略变更（替代 v1.0 的无缝循环）

1. 视频结构：0~3 秒 转身+摆定 pose；3~5 秒 站定，仅轻微呼吸 + 火焰持续燃烧。
2. 前端**播放一次后定格末帧**（pose 帧），不循环转身。
3. 定格后氛围感由现有 `.ov8-hero-motion` 代码动效（微粒/扫描光/光环旋转）持续承担，画面不会"死"。
4. v1.0 第 6 节"无缝循环后处理"作废，改为：核对末帧姿势清晰稳定、无残影抖动即可。
5. 手动展开 Hero 时从第 0 秒重播（重新看一次转身），播完仍定格。
