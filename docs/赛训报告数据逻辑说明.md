## 2. 数据库表结构

### 2.1 核心表

| 表名 | 记录粒度 | 用途 |
|---|---|---|
| `training_sessions` | 一场训练赛（日期+对手） | 训练赛元数据 |
| `training_rounds` | 单个回合 | 回合级细节（地图/阵营/战术执行/失误/首死） |
| `matches` | 单张地图比赛 | 地图级比分和胜负 |
| `briefing_items` | 单条赛前指令 | 教练下达的战术指令 |
| `tactics` | 单条战术 | 全队战术库模板 |
| `player_stats` | 单场单选手 | K/D/A/ADR/Rating |
| `players` | 单个选手/职员 | 队员档案（昵称/头像/位置/状态） |
| `special_events` | 单条事件 | 特殊日期标注（放假/被放鸽子等） |

### 2.2 训练回合关键字段

```
training_rounds
├── session_id        → 关联 training_sessions
├── round_number      → 回合序号
├── map_name          → 标准地图名（Mirage/Dust2/...）
├── team_side         → CT / T
├── command_text      → 教练点评文本
├── first_death_reason→ 首死ID + 时间 + 原因
├── round_result      → win / loss
├── players_involved  → 逗号分隔的选手ID
├── issue_grenade     → 道具失误标记（0/1）
├── issue_position    → 站位失误标记
├── issue_aim         → 枪法失误标记
├── issue_comms       → 沟通失误标记
└── issue_tactics     → 战术执行失误标记
```

### 2.3 约束条件

```
briefing_items:  team_side IN ('T','CT') NOT NULL
training_rounds: team_side IN ('T','CT'), round_result IN ('win','loss')
```

## 3. 数据同步流程

### 3.1 同步脚本

**文件**: `backend/scripts/sync_tencent_api.py`
**语言**: Python 3
**依赖**: `requests`, `openpyxl`

**执行流程**（每个文件独立）：

```
① manage.export_file (format=xlsx)
        ↓
② manage.export_progress (轮询直到 progress=100)
        ↓
③ HTTP 下载 XLSX 字节流
        ↓
④ safe_load_workbook (styles.xml 剥离兼容)
        ↓
⑤ openpyxl 逐行解析
        ↓
⑥ SQLite INSERT / UPSERT (WAL 模式，事务包装)
```

### 3.2 各表同步策略

| 表 | 策略 | 说明 |
|---|---|---|
| `tactics` | **全量替换** (DELETE + INSERT) | 战术总表是模板数据，每次全量刷新 |
| `briefing_items` | **按 session 覆盖** (DELETE WHERE session_id) | 每日简报按日期+对手覆盖 |
| `training_rounds` | **按 session 覆盖** | 训练日志按日期+对手覆盖 |
| `matches` | **UPSERT** (INSERT OR REPLACE) | 按 date+opponent+map 去重 |
| `player_stats` | **UPSERT** | 按 match_id+player_id 去重 |

### 3.3 触发方式

| 方式 | 机制 | 时间 |
|---|---|---|
| 手动 | `POST /api/internal/sync-tencent` → `execFile(sync_tencent_api.py)` | 任意 |
| 定时 | Ubuntu cron: `30 17 * * 1-6` | 每天 17:30（周一至周六） |

```python
}

```

### 4.2 对手名归一化

```python
OPPONENT_ALIASES = {
    'mongolza':        'Mongolz.A',      # Mongolz.Academy 简写
    'mongolz academy': 'Mongolz.A',
    'mongolz.academy': 'Mongolz.A',
    'nexvoid':         'NEXTVOID',        # 拼写错误
    'nextvoid':        'NEXTVOID',
    'thecube':         'THE QUBE',        # theCUBE → THE QUBE
    'the qube':        'THE QUBE',
    'the':             'THE QUBE',        # sheet 名截断: "0608_vs_the"
}
```

### 4.3 占位符/垃圾数据过滤

```python
# 被跳过的对手名
BLOCKED_OPPONENTS = {'OPPONENT', '未知', '___', 'match_data', 'MATCH_DATA'}

# 被跳过的地图名
BLOCKED_MAPS = {'', 'UR 队员统计', '地图'}

# 数据完整性 SQL 过滤（matches 表查询时）
matchIntegrityFilter = """
    match_date IS NOT NULL AND match_date != '' AND length(match_date) >= 8
    AND opponent NOT IN ('match_data', 'OPPONENT', '___')
    AND map_name IS NOT NULL AND map_name != ''
"""
```

### 4.4 失误分类（关键词匹配）

| 类别 | 列名 | 关键词示例 |
|---|---|---|
| 道具 | `issue_grenade` | 丢呲、烟雾弹、闪光、手雷、没丢好、白队友... |
| 站位 | `issue_position` | 走位、漏点、没观察、站位、peek、拉、压、顶... |
| 枪法 | `issue_aim` | 枪法、没对过、马枪、空枪、对枪... |
| 沟通 | `issue_comms` | 沟通、信息、交流、喊、call、没说... |
| 战术 | `issue_tactics` | 战术、没按、违抗、违反、未执行、没发布... |

匹配来源：`command_text`（教练点评）和 `first_death_reason`（首死原因）拼接后的文本。

### 4.5 训练日志 sheet 名解析

```
格式: {MMDD}_vs_{OPPONENT}
示例: 0608_vs_THE_QUBE → 日期=2026-06-08, 对手=THE QUBE
```

### 4.6 比赛数据 sheet 名解析

```
格式: {MMDD}_{OPPONENT}_M{序号}
示例: 0525_TyLoo_M1 → 日期=2026-05-25, 对手=TyLoo, 地图1
```

## 5. Dashboard API 数据模型

### 5.1 端点

```
GET /api/training/dashboard?start=YYYY-MM-DD&end=YYYY-MM-DD
Authorization: Bearer <JWT>
```

### 5.2 查询概览

| 查询 | 数据源 | 用途 |
|---|---|---|
| `overview` | `training_sessions LEFT JOIN training_rounds` | 训练赛场次、总回合数 |
| `matchOverview` | `matches` (带 matchIntegrityFilter) | 地图级胜负统计 |
| `matchSummary` | `training_sessions LEFT JOIN training_rounds` | 按 session 聚合的回合数 |
| `allMatches` | `matches` (带完整性过滤) | 所有比赛记录（用于 enrichment） |
| `validSessionKeys` | 从 matchSummary 提取 | "date\|opponent(lowercase)" 集合 |
| `filteredMatches` | allMatches ∩ validSessionKeys | 三表校验后的匹配记录 |

### 5.3 三表联动校验逻辑

```
validSessionKeys
    = { "2026-06-05|wydo", "2026-06-04|modun", ... }
    = Set<"date|opponent_lowercase">

allMatches (所有 matches 表记录)
    ↓ 逐条检查
    key = match_date.split(' ')[0] + '|' + opponent.toLowerCase()
    
    if key ∈ validSessionKeys → 计入 filteredMatches（统计用）
    if key ∉ validSessionKeys → 跳过（该比赛缺少训练日志）
```

**最终 response 使用的值**：
- `total_matches` = overview.total_matches（仅来自 training_sessions 有对手名的记录）
- `total_wins/losses/draws` = 从 filteredMatches 统计
- `enrichedMatchSummary` = matchSummary 各行 + 匹配到的 filteredMatches 数据

### 5.4 比赛记录 enrichment

每条 matchSummary（session）会尝试匹配 allMatches 中的记录：

```
session: date=2026-06-04, opponent=Modun
  → key = "2026-06-04|modun"
  → 查找 matchesByKey["2026-06-04|modun"]
  → 找到 2 条 match (Mirage win, Nuke draw)
  → enriched: { rounds: 48, total_maps: 2, map_wins: 1, map_losses: 0, map_draws: 1 }
```

### 5.5 完整返回值结构

```json
{
```

## 6. API 接口一览

| 路由 | 认证 | 用途 |
|---|---|---|
| `GET /api/training/dashboard` | JWT | 赛训报告主数据（支持 ?start/end/days） |
| `GET /api/training/report/:sid` | JWT | 单场联动报告（简报+回合+战术） |
| `GET /api/training/match-records` | JWT | 按地图筛选比赛记录（弹框） |
| `GET /api/training/round-details` | JWT | 回合详情筛选查询 |
| `GET /api/training/opponent-stats` | JWT | 对手统计数据 |
| `PUT /api/training/rounds/:id/players` | admin | 编辑回合关联选手 |
| `POST /api/internal/sync-tencent` | 内网 | 触发实时同步 |
| `GET /api/matches/grouped` | JWT | 近期比赛按日期+对手分组 |
| `GET /api/players` | — | 队员列表（支持 ?division/status/team_type） |
