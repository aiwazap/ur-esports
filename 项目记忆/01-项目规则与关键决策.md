# 项目规则与关键决策

## 执行边界
- Windows 本地 worktree 是代码开发副本，不等于 3001 或 3000 的完整数据环境。
- 本地 SQLite 数据库、`.env`、uploads 与服务器环境分开管理。
- 生产 3000 数据只允许单向拉回本地，禁止本地数据反向覆盖生产。
- 默认先本地验证，再推 3001 验收；只有 Aiwa 明确授权才允许推 3000。

## 数据使用决策
- 当前活跃开发的 FACEIT SEA worktree 位于 `D:\Agent files\codex\projects\worktrees\ur-esports\faceit-sea-task-board`。
- 本地服务默认读取各自 worktree 下的 `backend\data\ur_esports.db`，除非 `.env` 或环境变量显式设置 `DB_PATH`。
- 已确认 3001 数据备份位于 `D:\Agent files\_rollback\AgentFiles_Migration_Backup_20260710_160607\ur-esports-dev\backend\data\ur_esports.db`，但它不是当前 worktree 默认正在使用的数据库。

## FACEIT SEA 任务口径
- 当前 FACEIT SEA 冲分目标只统计已确认参赛队员，教练不进入 KPI。
- `HZ / HZZZZZ` 是教练，不计入 FACEIT SEA 队员列表、平均 ELO、净胜压力或 API 同步队员范围。
- 当前已确认计入 KPI 的 FACEIT SEA 队员：`4ever / L1XYyy`、`glong / NDWSS`、`melody / Me1odyovo`。
- 目标值：计入队员平均 ELO 达到 `3200` 才算完成。
- `azura 小号 / -maider666` 不再计入当前任务；本地初始化和接口启动时均应将其置为 `is_active=0`。
- 首页 FACEIT 卡展示队员平均目标、剩余分差、计入队员个人 ELO + 本月场次；个人 ELO 按本月场次降序排列。
- FACEIT 记录当前口径为“今日场次记录”，每场一行展示 `日期 / 时间 / 地图 / 比分 / 赛事`；赛事字段区分 `排位` 与 `联赛`，ESEA/Open/League/Tournament 等赛事名或队列命中时归为联赛。
- FACEIT 相关模块使用黑色 + 橙色视觉口径，避免混入赛训首页蓝紫主色。
- FACEIT 同步只使用后台一个 `Server side API Key`，保存在 FACEIT SEA worktree 的 `backend\.env`；不需要、也不应要求每个队员提供 API Key。
- FACEIT 战绩同步入口为后台管理接口 `POST /api/faceit-sea/sync-matches`，只同步计入 KPI 的 3 名有效队员相关战绩。
- 首页 FACEIT 个人 ELO 表格口径：列为 `ID / ELO / 今日场次 / 本月场次`；`ELO`、`今日场次`、`本月场次` 均为可点击排序标签，点击同列在 `降序 / 升序` 间切换，默认按 `本月场次降序` 展示。
- 首页最终结构口径：头图 Hero 后依次为 `即将开始赛事 / 赛事记录 / 选手数据` 三卡首排、`FACEIT SEA` 黑橙独立行、`训练赛记录 / 个人数据 / 失误类型分布` 抹茶绿三卡、`近期训练重点 / 地图胜率` 45/55 双卡、底部 `核心功能 / 快捷操作` 两组 2x3。
- 首页展示占位数据允许集中写在 `frontend/src/pages/Overview.jsx` 顶部 fallback 常量中，用于接口暂无字段时撑开视觉布局；当前包括训练个人数据、失误分布、6 张地图胜率。FACEIT 首页个人 ELO 可追加 `0Z / drace` 占位行，但后端 KPI 仍只统计 3 名有效队员。

## 首页 Hero 与 FACEIT 首屏交互口径
- Hero 以浏览器会话为边界：每个新会话第一次进入 `/overview` 时展开，`5s` 后只自动收起一次；会话内后续再次进入首页默认收起。
- 用户对 Hero 做任何手动展开或收起后，立即取消首次自动收起计时；之后手动展开必须一直保持，不得再次自动收起。
- 首次标记使用 `sessionStorage.ov8HeroIntroSeen=1`，不再由登录页重复写入 pending 标记。
- 首页 FACEIT SEA 独立行桌面端必须完整显示 `平均 ELO / 个人 ELO / 今日记录` 三列；窄屏按三块纵向堆叠，禁止固定高度裁掉任何一列。
